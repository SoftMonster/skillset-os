# Software development

A nested skillset. Pick the member whose "Use when" matches the request and read its instructions; for a nested skillset or a zip, run `python3 <top>/scripts/skillset.py open <path>` to get the file to read.

`software-dev-best-practices` is the baseline checklist: apply it alongside whichever member handles the task, in proportion to its size. When the person gives a time limit, `time-bounded-file-improvement` sets the pace and priorities.

**Adopted projects:** `repo-adoption` brings a repository or app into the skillset (`adopt-repository`) and holds a `develop-PROJECT` member for each one adopted. Each keeps its source in its own `app/` folder and coordinates the members below for every change.

Most tasks use one member. Larger ones chain them, and each member names the next where it matters:

- **Unfamiliar code:** `codebase-orientation` first. Its `scripts/detect_stack.py` finds the real build, test and lint commands and is reused by other members.
- **New work:** `plan-feature` (with `api-design` or `database-design` for contracts and schemas), then `implement-feature` with `write-tests`, then `code-review`, `git-workflow` and `ci-cd-pipeline`.
- **Something broken:** `debug-issue` for errors and wrong behaviour, `performance-tuning` for slowness, `security-review` for vulnerabilities.

`<top>` in these members means the installed skillset folder, the one holding the top `SKILL.md`.
